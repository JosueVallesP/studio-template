# Visual method for diagrams and frameworks

Adapted from Josué's `visual-philosophy` skill. Two beliefs sit under it: a visual is an argument, so its shapes should make true claims; and the meaning should live in the shape, so that with every label deleted you'd still see the idea.

## 0. State the idea and find its logic

Say the idea in one or two plain sentences, using the brief's claim. Then find the logic underneath: a contrast between two states, a change from one state to another, a difference in size, or a relationship that holds every time. If there's none, say so and send the brief back.

## 1. Purpose (teleology)

Who looks at it, what they already know, and what they should be able to do or believe after. Where it lives and whether it must stand alone (on social, it must). The purpose decides what stays.

## 2. The parts (ontology)

List the things the idea involves. Check that each is really separate, at the right level, and needed. Setup usually doesn't belong in the visual. Boxes inside boxes claim how the world divides; make sure you'd defend the claim.

## 3. How they relate (logic)

Name the relationship and match it to a form, using the table in `<plugin>/taste/rules/diagram-form.md`. Check the argument holds in every case, not just some.

## 4. The mechanic

Try the six mechanics under "Prefer these mechanics, in this order" in `<plugin>/taste/rules/diagram-form.md`, and use the first one that carries the idea without leaning on labels. That file holds the list.

Three rules for all of them: two states read as a switch and three or more read as growth; when the idea is a feeling, draw the feeling, not a process; let the structure be the argument.

Prefer shapes from the brand's "Recurring shapes" when one fits the idea.

## 5. How sure we are (epistemology)

Visuals look more certain than words. Don't draw exact proportions nobody measured. If categories blur in real life, show it.

## 6. How it will be read (hermeneutics)

Arrows can mean causes, leads to or becomes: make only one reading fit. Size reads as importance, up as more, left to right as time, center as core. Map the order of the sentence to the order on the page. Give the eye one place to start.

## 7. Which signs (semiotics)

Prefer familiar shapes and symbols. Use as few labels as the visual needs, in the reader's words. Keep a plain headline that states the idea.

## 8. Make several, then cut

Make the drafts different in mechanic, not just layout. Remove every element that doesn't serve the purpose. Stop when removing one more thing would break the idea.

## 9. Test

Run the tests in `<plugin>/taste/rules/legibility.md`: delete the labels, the stranger test, the wall test.
