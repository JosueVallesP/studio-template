# What the studio does without being asked

A skill is an instruction, and an instruction can be skipped on a bad run. A hook is a script Claude Code runs on its own at a fixed moment, every time. The studio uses seven. They live in `.claude/hooks/` and are wired up in `.claude/settings.json`, and they come with every update.

| When | What runs | What it does for you |
| --- | --- | --- |
| You open the studio (new session or resume) | `session-start.sh` | Puts the state in front of Claude before you type: setup stage, canon counts, pieces by state, open proposals, files waiting in `inbox/`, the last lines of `sessions/log.md`. You never start with "where were we". If the last save didn't reach GitHub, it says so and why, so Claude can tell you. On a person's first visit it also asks the first reply to open with the welcome in `docs/welcome.md`, the setup order and what they can do any time, whatever they typed. The first session after a new studio version arrives, it runs the install check once and passes on only what needs you: something missing, or a bank grown big enough that `/tidy` should run. |
| A crew agent is about to write a file | `guard-writes.py` | Holds each role to its own files: the writer writes drafts, the editor and the judge write reviews, and so on. `guard-writes.py` holds the lists, one line per role, and is the one place they're written down. Any crew agent trying to write the canon is denied with the reason. The main session (you, present) is never blocked, because setup, `/learn` and `/review` write the canon with you in the room; the main session and the job commands keep rule 6 by instruction. |
| A crew agent is about to read a file | `guard-reads.py` | Keeps every crew agent out of `bank/swipe/`, the whole posts the person saved from other people. The crew works from `bank/swipe-file.md`, which keeps the moves and one short quote, so the writer never has someone else's sentences in front of it. The main session reads `bank/swipe/` when the person asks to see a saved post. |
| A crew agent is about to run a command | `guard-bash.py` | Holds each role to its own short list of the studio's scripts and read-only git; `guard-bash.py` holds the lists. Only the editor and the judge may call the detector, and only they and the librarian may run `voiceprint.py`. Redirects, `$( )`, backticks, newlines and a lone `&` are denied, and an output flag (`--out`, `--targets`, `--log`) may only name a path under `pieces/` or `bank/voiceprint/`. Anything else is denied with the reason. The main session isn't held to a list, but a short list of commands that destroy work (deleting a folder, `git reset --hard`, a force push, `git clean`, throwing away every change, deleting a branch with `-D`) asks first: the app shows its own approval prompt, because the save after every reply would push the damage to GitHub before anyone noticed. Deleting inside a temp folder and the studio's own scripts pass. |
| Claude is about to send, post, book, move or cancel something in your name through any connector (Blotato, Metricool, AuthoredUp, Buffer, LinkedIn, Gmail, a HubSpot blog post, a Make scenario and the like) | `guard-publish.py` | Asks first, through the app's own approval prompt, so nothing goes out in your name without a click from you. It goes by what the tool does, not by a list of names, so a connector added later is covered too. Reading (the schedule, your numbers, your inbox) and email drafts pass. The rule in words is in `skills/setup-sources`, "Publishing"; this makes it hold even on a bad run. |
| A draft file is written (`pieces/*/draft-v*.md`) | `check-draft.py` | Runs `check-mechanical.py`, `check-human.py`, `check-prose.py` in piece mode, `voice-diff.py` when you have a corpus, and `check-stitch.py` (your sentences lifted word for word and not marked verbatim; `--cap 4` on an essay). The mechanical, prose and stitch fails go back to whoever wrote it as fails to fix; check-human's flags go back beside them as evidence for the editor, not fails. A draft that fails the mechanical checks can't reach the editor unseen. The detector is never called here. |
| Any other file you'll read is written (finals, briefs, reviews, `proposals.md`, canon drafts, `YOUR-STUDIO.md`) | `check-draft.py` | Runs `check-prose.py`: the house rules a script can see (`skills/craft-house-rules`). Fails go back to be fixed; likely breaks come back as flags. Your own words are never checked: `material/`, `inbox/`, `journal/`, everything in `bank/` (the idea bank and the rewrites included), `canon/bank/`, anything quoted, and the canon fields that hold what you said. |
| Claude finishes a reply | `check-reply.py` | Runs `check-prose.py --mode reply` on the reply: the same house rules, plus the two the studio's messages most often break (narrating its own process, filler praise). A script-level fail (an em dash, a filler opener, machine vocabulary, process narration) sends the reply back once to be said again plainly. The second time through it lets the reply stand, so nothing loops, and the breaks become a note in front of Claude before it answers your next message. Flags never block. Replies under twelve words are skipped. A rule broken twice in one session is noted in `studio-notes.md`. |
| Claude finishes a reply and files changed | `on-stop.sh` | Runs `scripts/save.sh` first, which scans what's about to be saved for passwords, API keys and tokens (`scripts/scan-secrets.py`; one stops the save, and the next session says which file and what kind, never the key), then commits, appends one line to `sessions/log.md` (time, which files changed) and pushes; then mirrors to the dashboards when they're connected. A sync that fails leaves a line with the reason, and the next session start tells you your dashboard may be out of date; the next sync that works clears it. A file over 50 MB is left out of the save and named, and audio and video in `inbox/` are never saved to GitHub (the text version is). When a save doesn't reach GitHub, the next session start says so. You never type git. In the studio's own master repo it does nothing. |

## The session bookends

The start hook opens the session. `/end` closes it: three lines said back to you (made, decided, waiting), `/learn`'s list of choices to keep, and an entry in `sessions/log.md`. The stop hook saves the files; `/end` saves what they meant. The librarian reads the log when it counts.

## If a hook gets in the way

A hook that denies a write prints why. If a crew agent needs a file outside its list, that's a sign the skill is asking the wrong role to do something, so write it to `studio-notes.md`. To turn a hook off, remove its block from `.claude/settings.json`; the next update puts it back, so a lasting change belongs in the studio repo.

The write guard's lists are in `.claude/hooks/guard-writes.py`, one line per role, and the command guard's in `.claude/hooks/guard-bash.py`. Those two files are the source; any other page that names a role's files points at them.
